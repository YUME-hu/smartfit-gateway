# 实验 E3：界面帧率与刷新开销

> 目的：给出"界面流畅度"与"显示子系统开销"的量化依据。
> 这一项容易被含糊过去（"跑起来挺流畅"），但有数字才能在论文里被检验。

---

## 1. 指标定义

两个不同的东西，必须分开说：

| 指标 | 定义 | 本实验中的含义 |
| --- | --- | --- |
| **实际重绘帧率** | 每秒完成多少次显示刷新（`LV_EVENT_REFR_READY` 计数） | 表盘真实产出的帧数 |
| **能力上限** | LVGL 刷新周期 16ms → 理论 62fps | 内容每 tick 都变时才能达到 |

用 `uiFrames`（每次 REFR_READY +1）作为计数器 —— 它是"完成了一次刷新"，不是"循环跑了一圈"。

## 2. 实验条件

| 项 | 值 |
| --- | --- |
| 日期 | 2026-11-26 12:53–12:57 |
| 页面 | 表盘页（鲸鱼动画在跑，无触摸） |
| 息屏 | 关闭（保持常亮） |
| 采样 | 25Hz 照常 |
| 统计 | 每 5 秒打印一次累计 `ui帧`，按 60 秒窗口切分 |

## 3. 结果（3 × 60s）

| 窗口 | 时间 | Δ帧 | fps |
| --- | --- | --- | --- |
| 1 | 12:53:00 → 12:54:00 | 625 | **10.4** |
| 2 | 12:54:00 → 12:55:00 | 699 | **11.7** |
| 3 | 12:55:00 → 12:56:00 | 698 | **11.6** |
| 全程 | 240 秒 | 2722 | **11.3** |

## 4. 为什么是 11 fps，而不是 62 fps

因为**界面本身没有那么多东西要重画**：

- 鲸鱼动画每 **160ms** 换一帧 → 6.25 次/秒
- 时钟/电量等文本约 1 次/秒
- 其余是零散的重绘（触摸、状态变化）

LVGL 在 PARTIAL 模式下**只重画脏区**，没有脏区就不刷。所以 11.3 fps 是
"**内容变化的频率**"，不是"渲染能力的上限"。

这一点对功耗是有利的：QSPI 只在真正需要时工作。同窗口的 `flush` 统计显示
每次刷新平均 **1039 µs**、5 秒内约 256 次条带推送。

## 5. 与 M1a 的 62fps 的关系（不要混用）

M1a 那次测的是**连续动画场景下的能力上限**（每个刷新周期都有脏区），得到 62fps。
本实验测的是**真实表盘的产出帧率**，11.3fps。

论文里引用时必须写清是哪一个 —— 混用会得出"帧率从 62 掉到 11"的错误结论。

## 6. 局限

1. 只测了表盘页；训练页/设置页的重绘更少
2. 未测触摸滑动时的瞬时帧率（拖动滑块会明显增加重绘量）
3. `uiFrames` 计的是完整刷新次数，一次刷新可能包含多个条带推送（在本实验中平均约 4.9 个）
