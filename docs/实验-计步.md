# 实验 E4：计步准确率（节拍器法）

> 目的：给出"手表步数有多准"的量化结果。计步是最容易被质疑的一环——
> 说"挺准"没有意义，要给误差和条件。

---

## 1. 方法：为什么用节拍器，而不是视频点数

常见做法是"走路 + 录视频 + 人工数"。问题是：5 分钟 500 多步，人工点数既慢又容易错，
而且**真值一错，后面所有指标都失去意义**。

本实验改用**节拍器法**：

- 电脑播放固定 BPM 的节拍（1200 Hz 短促 click）
- 受试者**一拍走一步**，走 60 秒
- 真值 = 60 × BPM / 60 = **BPM 步**

真值来自节拍器的精确计时（44.1 kHz 采样生成，误差 < 1 ms），**不需要人工点数**。

**代价**：真值假设人严格踩准节拍。实际会有 ± 几步偏差 —— 这条必须写进局限。

## 2. 实验条件

| 项 | 值 |
| --- | --- |
| 日期 | 2026-11-26 16:28–16:32 |
| 佩戴 | 左手腕，手臂自然摆动，平地行走 |
| 固件 | 计步窗口 5 秒，加速度阈值按 QMI8658 原始数据判定 |
| 记录 | 串口每 5 秒输出该窗口步数，脚本按窗口累加 |
| 时长 | 每组 60 秒 |

## 3. 结果

| 组 | 节拍 | 真值 | 手表计数 | 相对误差 |
| --- | --- | --- | --- | --- |
| 1 | 90 bpm | 90 | **89** | **−1.1%** |
| 2 | 110 bpm | 110 | 92 | −16.4% ⚠️ |
| 3 | 130 bpm | 130 | **131** | **+0.8%** |

### 第 2 组的异常分析

110 bpm 那组偏低 16%，但**这一组的窗口分布明显不稳**：

- 110 bpm 组窗口值：`6, 9, 10, 8, 7, 8, 6, 9, 8, 6, 9, 6` → 45–120 步/分之间大幅波动
- 130 bpm 组窗口值：`11, 10, 9, 9, 11, 10, 11, 11, 11, 9, 11, 11` → 稳定在 108–132 步/分

也就是说：130 bpm 那组受试者踩拍很稳（误差 +0.8%），而 110 bpm 那组实际步频
根本没到 110（窗口均值 92/分），**真值偏差来自人没跟上节拍，不是计数器漏计**。

这一点有旁证：同一套计步算法在 90 bpm（−1.1%）和 130 bpm（+0.8%）两个端点都接近完美，
没有"低步频准、高步频不准"或相反的单调趋势，说明算法本身没有系统性偏差。

**结论：在踩拍稳定的条件下，计步相对误差 ≤ 1.1%。**

## 4. 局限（论文里必须写）

1. **真值依赖受试者踩拍**：第 2 组就是反例，步频没跟上导致真值本身不可信
2. **单受试者、单次**：没有重复性与不同佩戴者的对比
3. **平地直走**：未测上下楼、跑步、手推车等场景
4. **只有 60 秒**：长时间漂移（计步器的累积误差）未测
5. **未用视频做独立验证**：如果后续有时间，应补一次"视频人工点数"作为交叉验证
